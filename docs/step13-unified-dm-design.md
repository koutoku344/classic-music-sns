# STEP13 設計確定 — 共通DM

## 2026-10-23 確定仕様
- **募集専用チャットは作らない**。すべての1対1メッセージを共通DMに集約し、会話はユーザーの組み合わせで一意にする。
- 募集からは応募者／主催者のプロフィールを開き、プロフィールの「メッセージ」から会話を開始する。
- 募集終了後も既存の会話で送受信できる。募集を削除してもDMは残る。
- 新着DMはアプリ内通知＋メッセージ一覧の未読件数で知らせる。
- 会話画面とメッセージ一覧は、表示中・ブラウザが可視の際に約10秒間隔で取得する。
- メッセージ一覧に表示するのは**相手・最新メッセージ・未読件数のみ**。募集・応募による分類や募集名は表示しない。
- 送信可能なデータはテキスト（最大2000文字）。ファイル添付、編集、削除はSTEP13初期範囲外。
- プロフィールを持つログインユーザーが、他のプロフィールを持つユーザーとのDMを開始できる（募集参加・フォローの有無には依存しない）。迷惑連絡の防止策は後続課題。

## データと権限
- `026_create_conversations.sql` は **未適用**。実装変更に伴い以前の募集単位スキーマを共通DMスキーマへ全面更新したため、必ず最新ブランチのファイルを確認してから適用する。
- `conversations`: 正規化した二者のUUIDペアで一意。募集へのFKは持たない。
- `direct_messages`: 送信者と本文。SELECT・INSERT・既読更新は常に両参加者だけを許可。
- 新着通知はDBトリガーで作成し、メッセージ送信と同一トランザクションで整合性を保つ。
- 通知一覧は会話IDのみ返す。会話の内容はメッセージAPIの認可を通して取得する。

## テストと適用順
1. `npm run test:step13:check`：静的テスト・認可テスト・型チェック・build。
2. SQL 026適用前に最新SQLの最終レビュー。Neonで026を実行。
3. Backend・Frontendをデプロイ。
4. 専用A/Bアカウントでプロフィール→DM作成→送信→通知→未読→既読→返信→権限制御を確認。
5. UI目視確認後にmain統合。

# STEP10-1 フィードバック・交流機能：要件整理（案）

更新日：2026-10-17
ブランチ：`feat/step10-feedback`（STEP9をマージしたmainから作成）

## 1. 目的

STEP9で投稿・閲覧ができるようになったSonoliiに、演奏者が投稿への感想を受け取り、音声の特定箇所について改善意見をやりとりできる最小の交流機能を追加する。

既存の要件定義書 `docs/requirement.md` の FED-01〜05、COM-10を基礎とする。通知・フォロー（FOL/NOT）は後続STEPを基本とし、STEP10に含めるかは仕様決定時に切り分ける。

## 2. 既存の確定仕様

- `posts.comments_enabled` はSTEP9ですでに保存済み（初期true）。コメント送信APIで必ず検査する。
- `profiles.visibility`に従い投稿表示を許可。現時点では`public`は第三者閲覧可能、`private`と`followers`は投稿者本人のみ。
- 投稿には音声最大1件。曲の登録は任意だが、曲を選んだ場合は音声必須。
- 投稿の公開可否や認可判断をFrontendだけに委ねない。R2音声本体とDBコメントは分離し、コメントに音声オブジェクトをコピーしない。
- 投稿そのものを削除した場合、紐づくコメントも閲覧不可（DB上はFK ON DELETE CASCADE等をSTEP10-2で検討）。

## 3. STEP10への提案

| 機能 | 推奨 | 備考 |
| --- | --- | --- |
| 一般コメント投稿／一覧 | 実装 | 本文最大1000文字（提案）、空文字不可 |
| タイムスタンプコメント | 実装 | 秒数integerを保存、音声再生位置にリンク |
| コメント受付ON/OFF | 実装 | STEP9の既存設定を使う。OFFは新規投稿拒否、既存コメント表示は継続（提案） |
| コメント削除 | 実装 | コメント投稿者が本人のコメントを削除。投稿者が第三者コメントを削除できるかは要確認 |
| いいね | STEP10で実装を推奨 | 1アカウントにつき1投稿1いいね。解除可能。通知は後続 |
| コメント返信 | 後続またはSTEP10で最小の1階層 | MVPは通常コメントだけでも成立。要求の優先度を確認 |
| フォロー・通知 | 後続 | 自分宛フィードバックの確認は投稿詳細画面で可能とする |
| 匿名コメント | 不可（提案） | 投稿の匿名閲覧は可能、書込みはClerkログイン必須 |

## 4. 推奨するUIフロー

```text
投稿一覧 / 検索 / マイページ
  └ 投稿カードをタップ → 投稿詳細
      ├ 投稿内容 + 音声プレイヤー
      ├ コメント一覧（新しい順 or 古い順：要決定）
      │   ├ 通常コメント
      │   └ [01:23] このフレーズの強弱が良い → 押すと音声1:23へ
      ├ コメント入力
      │   ├ 文章入力
      │   ├ [現在の再生位置を付ける]（音声ありの投稿だけ表示）
      │   └ 送信
      └ いいね（採用する場合）
```

- 送信ボタン押下時に未入力・文字数超過等をエラー表示（STEP9と同じ操作方針）。
- `comments_enabled=false`ではコメント入力を非表示にして受付停止を明示。
- Timestampは `MM:SS` または `H:MM:SS`で表示し、音声の再生時間内かBackendでも検証する。Duration情報の信頼性に依存するため扱いはSTEP10-2の前に確定する。
- 再生位置のリンクは同じ投稿の音声プレイヤーを制御。音声未登録の投稿への時刻指定は拒否。
- 通常コメントもタイムスタンプコメントも同じコメントデータモデルで保存し、秒数はnull可のフィールドで表現する案。

## 5. 権限（推奨）

| 操作 | 匿名 | 他ユーザー | 投稿者本人 |
| --- | --- | --- | --- |
| 公開投稿のコメント閲覧 | 可 | 可 | 可 |
| 非公開投稿のコメント閲覧 | 不可 | 不可（フォロー未実装） | 可 |
| コメント作成 | 不可 | コメント受付ONかつ投稿閲覧可なら可 | 自分の投稿にも可（提案） |
| 自分のコメント削除 | 不可 | 本人のみ可 | 本人のみ可 |
| 他人コメント削除 | 不可 | 不可 | 投稿者による削除可否は要確定 |
| いいね | 不可 | 閲覧可なら可 | 自分の投稿へのいいね可否は要確定 |

コメントが投稿された後に公開設定がprivateになった場合、投稿と同じ認可条件で一覧・詳細を遮断する。

## 6. API/DBの方針（STEP10-2で詳細設計）

- `post_comments`：id、post_id、user_id、body、audio_timestamp_seconds(null可)、created_at等。FK、CHECK、INDEX。
- コメント一覧：`GET /posts/:id/comments?limit=20&cursor=...`、投稿者名と時刻を返す。ページング対応。
- コメント送信：`POST /posts/:id/comments`。JWT、プロフィール公開設定、コメント許可、対象音声の存在と時間範囲を検証。
- コメント削除：`DELETE /posts/:id/comments/:commentId`。本人・投稿者の認可仕様が確定してから実装。
- いいねを採用する場合は`post_likes(post_id,user_id)`で重複禁止、登録・解除API。
- 投稿削除後にコメント等の孤立データを残さないためFK整合性を定義する。

## 7. 非機能・コストの方針

- コメント・いいねはDBレコードで管理し、Cloudflare R2には保存しない。追加のR2料金はコメント送信自体には発生しない。
- 一覧ページング、必要なINDEX、レスポンスサイズ制限、書き込みのレート制限、不正文字列・XSS対策を実装する。
- 再生位置への移動はブラウザのHTMLAudioElement操作であり、通常は専用の音声変換やBackend処理を追加しない。
- 監査目的でuser_idと作成日時を保持し、セキュリティやプライバシーの要件に合わせて削除時のデータ取扱いを決める。

## 8. 未確定事項：STEP10-1で合意する

1. **いいね**をSTEP10へ入れるか（推奨：入れる）。
2. **コメント返信**をSTEP10へ入れるか（推奨：後続に回し、まず通常・時刻コメントを安定させる）。
3. **投稿者による他人のコメント削除**を許可するか（推奨：投稿者は自分の投稿のコメントを削除可。ただし乱用／透明性も検討）。
4. **コメントをOFFに変更した場合**、既存コメントを表示し続けるか（推奨：表示は続け、新規だけ不可）。
5. **時刻コメントの入力方法**（推奨：プレイヤー位置をワンタップで添付、秒数を手入力させない）。

上記を確定後にSTEP10-2のSQL設計へ進む。現段階でDB変更やBackend実装は行わない。

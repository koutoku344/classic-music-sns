# STEP15 UI/UX リリース品質レビュー

## 目標
STEP15終了時にWeb版の全画面がPC・iPhone Safari・Android Chromeで公開できるUI品質に到達する。
外観だけでなく、実データ、空状態、エラー、導線、キーボード/タッチ操作を含める。
本番DBの更新や課金機能はこのフェーズで無断追加しない。

## 初回コードレビューで確認した問題
| 優先 | 画面 | 根拠 | 対応 |
|---|---|---|---|
| P0 | マイページ | `MyPage.tsx` が `../data` の `recruitments` を表示し、本人の募集がない場合にもダミー募集を2件挿入 | 実APIによる本人の募集取得に置換 |
| P0 | マイページ | `me.following` / `me.followers` と `me.trophies` がモック値 | 実データに置換するか、未実装表示を撤去 |
| P1 | メッセージ一覧 | 会話開始がプロフィール起点になったのに「募集の承認後に開始」と案内 | 修正済み |
| P1 | メッセージ一覧 | 会話ゼロ件と名前検索一致なしが同じ表示 | 修正済み |
| P1 | マイページ | 料金が未確定のPremium宣伝と「20GB」表記 | 提供内容確定まで誤認を招かない表記に変更 |
| P1 | 検索 | 投稿・募集キーワード入力のたびに検索を発行し、通信中の結果がちらつく可能性 | デバウンス／再検索時の状態検証 |
| P1 | 検索 | 曲フィルターとキーワードの関係の説明が不足 | UI導線見直し |
| P2 | メッセージ詳細 | 10秒自動更新で表示内容を差し替える | 長い履歴・スクロール位置を実機確認 |

## 15-1 画面棚卸し
- 認証・初期登録
- ホーム・投稿一覧・投稿作成／詳細／編集
- 検索（ユーザー・投稿・募集）
- マイページ・他人プロフィール・フォロー
- レパートリー・練習記録・録音
- 募集作成／詳細／応募
- DM一覧／会話、通知
- 設定、アカウント、メディア管理
- 利用規約・プライバシー・ヘルプ
- 課金予定画面（未提供であることを明確化）

## 15-2 実装方針
1. モックや誤解を生むデータを削除（P0）
2. 正常・空・読み込み・失敗・アクセス拒否の状態を全画面で区別
3. ラベル、タップ領域、戻る導線、フォーム、レスポンシブを統一
4. UI回帰テストを拡充

## 15-3 最終確認（リリース判定）
- PC（Chrome、キーボード操作）
- iPhone Safari、Android Chrome（実機優先）
- 画面幅320px、375px、390px、768px、1280px
- 通信遅延、0件、入力エラー、通信失敗、長文、長い曲名
- 全主要導線のPlaywrightテストと目視8項目以上
- UI残課題がゼロ、または公開を妨げない軽微な課題のみ

## STEP15保存機能の導入手順
- SQL: `db/migrations/027_saved_items.sql`（Neonへの適用は型チェック・静的テスト成功後）
- API: `/me/saved`、`/me/saved/{post|recruitment}/:id`（本人認証必須）
- コミュニティの保存ボタン、マイページの保存済みタブ
- なおAPIデプロイとSQL適用前は保存ボタンを実環境で操作しない
- E2Eでは他ユーザーのフォロワー限定／非公開投稿の保存拒否、保存済み一覧からの閲覧制御、二重保存の冪等性を確認

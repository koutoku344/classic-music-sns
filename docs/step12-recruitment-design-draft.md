# STEP12 募集掲示板 — 仕様・実装方針（確認用ドラフト）

## 現状（main調査）
- `CreateRecruitment.tsx`, `RecruitmentDetail.tsx`, `RecruitmentCard.tsx`, `Search.tsx`, `Community.tsx` にUI雛形あり。
- 募集一覧・詳細・応募者は `features/sonolii/data.ts` のサンプル参照。投稿ボタンは画面遷移だけで保存しない。
- `backend/src/` に募集APIはなく、`db/migrations/` に募集テーブルなし（末尾023）。
- STEP11のプロフィール基本情報と投稿の公開制御は別。募集の公開制御は独立して定義する。

## たたき台（未確定項目は実装前に確認）
1. 募集は認証＋プロフィール登録済みユーザーが作成。曲は任意、楽器・地域は複数選択、本文は必須。
2. 公開一覧は募集中を優先し、募集終了も詳細は閲覧可。登録者だけ編集・募集終了・削除可。
3. 応募者は一人につき一募集に一件。申請→取り消し、主催者が承認・却下。承認した応募だけ連絡導線へ。
4. 詳細では主催者自身に応募ボタンを出さない。応募者名や応募状況を第三者に漏らさない。
5. 画面の音声録音UIは現時点でタイマーだけのモック。実録音・R2紐づけの扱いは別途決定が必要。
6. 募集閲覧の対象（public/followers/privateのプロフィール連動か、募集単位公開か）を決める。
7. STEP13メッセージ連携前は、個人間の連絡先を公開せず、承認後の連絡UIは機能準備中として扱うか決める。

## 実装単位（コマンド回数を削減）
- STEP12-A 設計確定 → migration 024以降、API契約、アクセス制御
- STEP12-B Backend＋Frontendをまとめて実装（チャット側でGitHubに反映）
- STEP12-C Neon適用（ユーザー側1回、DDL事前確認済み） → Backend/Frontendをまとめてデプロイ
- STEP12-D まとめて確認：静的/型/ビルド（1コマンドスクリプト）、読み取りE2E（1コマンド）、書き込みE2E（専用フィクスチャ・明示許可で別コマンド）
- 失敗時はテスト名・ファイル単位のレポートで切り分け。書き込みテストは独立実行し、既存データを変更しない。

## 要決定
A. 募集の公開範囲：全ユーザーに公開（推奨）／プロフィールの公開範囲に連動
B. 応募フロー：申請→主催者承認・却下（推奨）／応募即成立
C. 音声添付：STEP12で既存R2を再利用（工数増）／Phase2へ延期して入力UIを一時的に非表示（推奨）
D. 応募成立後の連絡：STEP13メッセージ実装まで「メッセージは準備中」を表示（推奨）／STEP12で簡易連絡手段を実装

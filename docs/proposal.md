# クラシック奏者向けサービス 企画書

## 1. コンセプト

**クラシック奏者が演奏活動を記録し、演奏を通じて他の奏者とつながるサービス。**

まずは「曲・レパートリー管理」「練習記録」「演奏履歴」により、一人でも利用価値を提供する。

その上で、演奏音声・画像の共有、フィードバック、募集掲示板を通じて、他のクラシック奏者との交流やアンサンブル活動につなげる。

### 基本コンセプト

> **一人でも利用価値があり、ユーザーが増えることでコミュニティとしての価値が高まるサービス**

サービス上では、

> **曲 → 演奏 → 人**

という流れで、好きな曲や演奏を起点に奏者を知り、交流へつながる体験を目指す。

---

## 2. 対象者

### メインターゲット

**趣味としてクラシック音楽を継続している20歳以上のアマチュア奏者。**

特に以下のような人を対象とする。

* 練習中・演奏済みの曲やレパートリーを管理したい
* 自分の演奏を記録して振り返りたい
* 自分の演奏について他の奏者からフィードバックが欲しい
* 他の奏者の演奏を聴きたい
* 他のクラシック奏者と交流したい
* 一緒に演奏する仲間を探したい

初期は成人アマチュアピアノ奏者を中心に検証し、将来的に他楽器へ展開する。

---

## 3. 課題

クラシック奏者には以下の課題があると仮定する。

* 練習中・演奏済みの曲や演奏履歴をまとめて管理しにくい
* 過去にどの曲をどのように演奏したか振り返りにくい
* 自分の演奏について他の奏者からフィードバックを得る機会が少ない
* 一般SNSでは同じ曲・楽器・目的を持つクラシック奏者を探しにくい
* 長時間のクラシック演奏は一般的な短尺SNSと相性が異なる
* アンサンブルをしたくても、条件の合う奏者を探しにくい
* 募集相手がどのような演奏・音楽活動をする人なのか判断しにくい

これらについては実ユーザーの利用状況およびユーザー調査によって検証する。

---

## 4. 解決方法・主要機能

### 基本方針

**「一人でも使える機能」から「演奏を共有する機能」「人とつながる機能」へ段階的に移行できるサービス**とする。

MVPでは演奏メディアとして**音声＋画像**を採用する。

クラシック演奏において音楽そのものを伝える中心的な情報は音声である一方、画像・プロフィールによって「誰が演奏しているか」「どのような奏者か」を伝える。

動画投稿については、ストレージ・Transcode・配信等の追加コストおよびシステム複雑性が大きいため、MVPでは実装しない。

実ユーザーから動画投稿・動画視聴に対する需要が確認された場合に追加する。

### 主要機能

| 機能                     | 内容                          |
| ---------------------- | --------------------------- |
| **曲・レパートリー管理**         | 練習中・演奏済み・レパートリー等を管理         |
| **演奏履歴**               | 曲ごとに過去の演奏音声・画像を蓄積           |
| **演奏投稿**               | 曲・コメント・演奏音声・画像をCommunityへ投稿 |
| **Community Feedback** | 演奏について他の奏者から感想・アドバイスを受ける    |
| **Timestamp Feedback** | 公開された演奏音声の特定箇所へコメント         |
| **Timeline / 検索**      | 曲・作曲家・楽器等から投稿・演奏・奏者を探す      |
| **プロフィール**             | 楽器・地域・レパートリー・公開演奏・活動目的等を掲載  |
| **Follow / 通知**        | 気になる奏者と継続的に交流               |
| **募集掲示板**              | 地域・楽器・曲・レベル等を指定してアンサンブル等を募集 |
| **練習記録**               | 日付単位で複数曲の練習時間・コメントを記録し、日付別 / 曲別に振り返る |
| **Schedule**           | 発表会・コンクール・レッスン等を管理          |

## 5. コミュニティへの導線

曲・レパートリー管理、練習記録および演奏履歴を個人利用の起点とし、ユーザーが必要に応じてCommunityへ参加できるようにする。

```text
曲を登録
    ↓
演奏を記録
    ↓
演奏履歴として保存
    │
    ├────────────────┐
    ↓                ↓
演奏を投稿         募集掲示板を利用
    │                │
    ↓                ↓
Feedback          募集・応募
    │                │
    └───────┬────────┘
            ↓
       他の奏者を知る
            ↓
          Follow
            ↓
       継続的な交流
            ↓
       一緒に演奏する
```

募集掲示板については、演奏公開を必須としない。

一方で、応募を検討するユーザーが募集者の音楽活動を確認できるよう、プロフィール・レパートリー・公開演奏を参照できる構成とする。

### 演奏投稿

MVPでは以下の形式を基本とする。

```text
曲
＋
演奏音声
＋
画像（任意）
＋
本人コメント
```

音声を演奏記録の本体とし、画像・プロフィールによって奏者本人や演奏時の雰囲気を伝える。

## 6. 動画機能の位置付け

動画には、音声だけでは伝わらない以下の情報を伝えられる価値がある。

* 演奏者本人
* 表情
* 姿勢
* 身体の使い方
* 手・腕の動き
* 楽器
* 演奏している空間・雰囲気

そのため動画機能自体を否定するものではない。

一方、動画を扱う場合は、

* 保存容量増加
* Transcode
* 配信
* 動画処理基盤
* 運用・監視

等の追加コスト・複雑性が発生する。

このためMVPでは、

> **動画が必要であることを仮定して動画基盤を構築するのではなく、音声＋画像でサービスを提供し、実ユーザーから動画に対する需要を確認する。**

という方針とする。

### 将来的な動画機能

需要が確認された場合、動画投稿機能を追加する。

動画は配信用に圧縮・変換し、元動画をそのまま長期保存・配信する方式は採用しない。

Freeユーザーにも動画機能を少量提供し、実際に体験した上でPremiumへ移行できるモデルを想定する。

想定例：

```text
Free
・動画投稿可能
・1動画 最大5分
・少量の動画を無料保存
・Storage全体 3GB

Premium
・動画投稿可能
・Freeより長時間・多数の動画
・Storage全体 20GB
```

具体的な無料動画本数およびTranscode処理量は、動画機能追加時のTranscode単価・利用状況を基に決定する。

## 8. KPI

| 分類           | KPI                         |
| ------------ | --------------------------- |
| Acquisition  | 登録ユーザー数                     |
| Activation   | 曲登録率、初回演奏登録率                |
| Engagement   | MAU、曲登録数、演奏登録数              |
| Community    | 投稿率、演奏共有率、Feedback数         |
| Connection   | Follow率、プロフィール閲覧数、相互交流ユーザー数 |
| 募集           | 募集投稿数、応募数、募集→応募率            |
| Retention    | D7 / D30継続率                 |
| Monetization | Premium転換率、MRR              |
| Cost         | ユーザーあたりStorage使用量           |

特に以下のユーザー遷移を重視する。

```text
登録
 ↓
曲・レパートリー管理
 ↓
演奏記録
 ↓
演奏を共有
 ↓
Community Feedback
 ↓
プロフィール閲覧 / Follow
 ↓
継続交流
```

動画については、

* 動画を投稿したいユーザーの割合
* 他ユーザーの動画を見たいユーザーの割合
* 音声＋画像では不足すると感じる割合
* 動画機能に対するPremium支払意向

を調査し、機能追加の判断材料とする。

## 9. マネタイズ方法

### Freemium + Subscription

基本的な曲管理・コミュニティ機能を無料で提供し、保存容量・高度な機能・将来的な動画機能等をPremiumで拡張する。

### Free

* 曲・レパートリー管理
* 基本的な演奏履歴
* 音声＋画像投稿
* Community Feedback
* プロフィール
* Follow
* 募集掲示板
* Storage：**3GB**
* メディア保持：**原則12か月**

### Premium

**月額1,000円程度を想定する。**

* Storage：**20GB**
* メディア長期保存
* 高度な演奏履歴
* 過去演奏比較
* 将来的な動画投稿枠の拡大
* 将来的な長時間動画投稿

動画機能を追加する場合もFreeユーザーに少量の動画投稿を提供し、利用価値を体験した上でPremiumへ移行できる構成とする。

StorageについてはFree 3GB / Premium 20GBのHard Limitを設けることで、ユーザー増加時の最大保存コストを制御する。

動画についてはStorage上限だけではTranscode費用を制御できないため、動画時間・本数・Transcode処理量にも上限を設ける。

## 10. 集客方法

### 基本方針

最初から「動画SNS」として集客するのではなく、**曲・レパートリー管理、練習記録、演奏履歴、クラシック奏者との交流**を入口としてユーザーを獲得する。

主な集客チャネル：

* Instagram
* X
* YouTube
* クラシック音楽関連コミュニティ
* SEO / Webコンテンツ
* 将来的には音楽教室・演奏イベント等との連携

### ユーザー獲得からCommunityまで

```text
Instagram / X / 検索
        ↓
「レパートリーを管理」
「自分の演奏を記録」
        ↓
       登録
        ↓
曲管理・演奏履歴
        ↓
音声＋画像をCommunityへ共有
        ↓
 Feedback・交流
        ↓
プロフィール閲覧 / Follow
        ↓
   募集掲示板
        ↓
   一緒に演奏する
```

**一人でも価値があり、ユーザーが増えるほどCommunityとしての価値が大きくなるサービス**を目指す。

## 11. 将来的な機能

### 動画投稿

実ユーザーから需要が確認された場合に追加する。

* Freeで少量投稿
* Premiumで投稿可能量を拡大
* 動画を配信用に圧縮
* 動画時間・保存本数・Transcode処理量を制御
* StorageはFree 3GB / Premium 20GBの範囲内で管理

### Teacher / Student

* 先生限定の演奏共有
* Timestamp Feedback
* 課題管理
* レッスン履歴・予定
* 生徒管理
* 生徒の演奏・成長履歴
* Teacher Dashboard

### Ensemble / Community高度化

* 高度な奏者検索
* Ensemble Project
* メンバー管理
* 練習日程調整
* 本番管理
* アンサンブル活動履歴

### AI演奏分析

現時点では費用対効果が不明確であるため開発対象外とする。

将来的にユーザー需要、技術的実現性、分析精度、運用コストの面で十分な価値が確認できた場合に再検討する。

## 12. 最重要検証事項

1. **曲・レパートリー管理に継続利用する価値があるか**
2. **演奏履歴を継続的に保存・振り返る価値があるか**
3. **音声＋画像の演奏投稿からユーザー同士のFeedbackが発生するか**
4. **曲・演奏を起点として他の奏者のプロフィール閲覧・Followにつながるか**
5. **「誰が・どのような人が演奏しているか」を音声＋画像・プロフィールで十分に伝えられるか**
6. **音声＋画像ではなく動画を投稿・視聴したい需要がどの程度存在するか**
7. **アンサンブル募集・応募の需要があるか**
8. **演奏・レパートリーを確認できることが奏者同士のつながりに価値を与えるか**
9. **Premiumに対する支払意向があるか**

特に動画については、MVPリリース前に必要性を決め切るのではなく、**実ユーザーの利用状況・要望を基に投資判断する**。

## 13. サービスの成長イメージ

```text
Stage 1
曲・レパートリー管理 ＋ 練習記録 ＋ 演奏履歴
「一人で使える」
        ↓
Stage 2
音声 ＋ 画像投稿
「演奏を共有できる」
        ↓
Stage 3
Feedback ＋ Follow
「演奏を通じて交流できる」
        ↓
Stage 4
募集掲示板
「一緒に演奏できる」
        ↓
Stage 5
需要に応じて動画投稿
「演奏者の姿も含めて共有できる」
        ↓
Stage 6
Teacher / Student・Ensemble
「クラシック演奏活動全体を支える」
```

最終的に、**個人の曲・演奏管理から、演奏共有、奏者同士の交流、実際の演奏活動までをつなぐクラシック奏者向けプラットフォーム**を目指す。

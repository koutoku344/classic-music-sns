# STEP9追加UI：投稿編集・削除と添付アイコン導線（STEP9-8の前に確認）

## 変更範囲

- `PostDetail.tsx`：投稿者本人のみ「…」メニューに「編集」「削除」を表示。削除前に確認ダイアログを表示。
- `app/posts/[postId]/edit/page.tsx`：`/posts/:postId/edit`編集画面を追加。
- `CreatePost.tsx`：新規・編集を共通化。本文 → 音声アイコン／画像アイコン → フィードバック → コメント受付 → 投稿操作。音声アイコンから録音／ファイル／過去の音声を選ぶ画面へ進み、同画面から曲選択へ進む。画像アイコンから新規画像／保存済み画像を選択。未入力でも投稿ボタンはクリック可能で、クリック後に検証エラーを表示。
- `postApi.ts`：PATCHとDELETE APIのFrontend実装。
- `RouteScreen.tsx`、`types.ts`：編集ルートを追加。
- `CreatePractice.tsx`：音声アイコンから録音／ファイル／保存済み音声選択欄を開く。未選択の曲がある場合「記録する」を押したあとにエラー表示。練習日・曲（必須）・分数・メモ・音声（任意）の項目／API body／バリデーション範囲は維持。
- `PracticeAudioPicker.tsx`：投稿／練習記録に合わせて説明ラベルを切替。音声ファイルの制約・アップロードAPIは変更なし。

**DBマイグレーション不要、Backendの変更なし。** 既存テスト投稿を保持したまま検証する。

## 最小の確認手順（ブラウザ）

### 投稿作成

1. `http://127.0.0.1:5173/posts/new`を開き、何も入力せず「投稿する」を押す。「本文・音声・画像のうち1つ以上を入力してください。」が出る。投稿ボタンが無効化されていないこと。
2. 音声アイコンを押す。録音／ファイル／過去の音声の3選択肢が出る。**既存の保存済み音声**を選択し、音声が確認できる。
3. 「演奏した曲を選択」から曲を選択する。「入力画面へ戻る」で曲と音声の選択内容が維持される。
4. 画像アイコンを押し、保存済み画像を選択。メイン画面に戻ったとき添付数が表示される。
5. 必要なら本文を入力し「投稿する」を押す。成功なら「投稿を見る」で詳細へ移動する。

### 投稿編集・削除

6. **自分の投稿**の詳細右上「…」を押すと「編集」「削除」が表示される。他人の投稿には表示されない。
7. 「編集」を押し、既存本文・曲・音声・画像・フィードバック・コメント受付の値が読み込まれることを確認する。
8. テスト用の自分の投稿を編集し、本文だけ追記して「変更を保存」。詳細に追記結果が残り、既存音声・画像が残る。テストデータは削除しない。
9. 「削除」を押すと確認ダイアログが表示される。**キャンセル**して投稿が残ることを確認する。実際の削除を試す場合は、残してよい既存データではなく新しく作った専用投稿のみを対象にする（今回は削除確認のみで十分）。

### 練習記録

10. `http://127.0.0.1:5173/practice/new`を開き、曲未選択で「記録する」を押すと「練習した曲を選択してください。」が表示される。
11. 曲を選択した後、音声アイコンを押して録音／ファイル／過去の音声の画面を開ける。音声なしでも、日付・時間等が妥当なら記録を保存できる（従来仕様）。
12. 練習記録の既存の編集画面でも曲・日付・時間・メモ・音声の既存情報が読み込まれることを確認。

## 注意事項

- 投稿の編集はBackendの`PATCH /posts/:id`で**投稿内容全体**を保存する。既存添付IDも一緒に送信するため、添付の誤解除に注意。
- 投稿削除は`DELETE /posts/:id`、所有者本人のみ。削除した投稿の`post_media`は消えるが`media`とR2の音声／画像は残る。
- 画像の保存可能数は最大5枚、音声は最大1件。音声があるとき曲は任意、曲を選んだとき音声は必須というルールを維持。
- 投稿編集画面で新規添付したファイルは、保存を中止してもメディア管理に残る。
- STEP9-8の総合テストは、このUI確認の後に再開。

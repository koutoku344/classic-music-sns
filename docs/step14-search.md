# STEP14 検索機能 — 第1実装

## 現状
- ユーザー検索：サンプルの配列を廃止し、`GET /users/search` と `public.profiles` に接続。
- 投稿：本文・作曲者・曲名のキーワード検索を既存の曲フィルターと組み合わせる。
- 募集：募集内容・作曲者・曲名のキーワード検索を既存の楽器・地域・レベル・目的・曲フィルターと組み合わせる。
- ページネーション：ユーザー検索は20件、投稿・募集は既存のカーソル式。
- 投稿公開範囲：既存の公開・フォロワー限定・本人の表示条件を維持。
- ユーザー横断検索：公開プロフィールのみを対象（非公開・フォロワー限定は列挙しない）。
- DBマイグレーション：第1実装では不要（既存テーブルを参照）。

## 確認したいUI・仕様
- ユーザー名の文字列検索と楽器・地域の組み合わせはAND検索。
- 投稿・募集のキーワードは本文／曲名／作曲者に対する部分一致（いずれか）。
- 自分が追加した独自曲の検索は、投稿側で `user_pieces` とJOIN済み。募集側は現状マスター曲に限定。
- 検索性能は規模拡大後に実クエリ計画で評価。必要なら `pg_trgm` + GIN を別マイグレーションで追加（無条件で大量インデックスは作成しない）。
